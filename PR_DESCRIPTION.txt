Title: feat!: add user stores, cross-app access, and SCIM provisioning 🚀

## 📝 Summary

Regenerates the SDK to cover new Organization surfaces — User Stores, Cross-App
Access, and SCIM provisioning on identity providers — along with new member access
levels, invitation roles, and pagination totals. Includes several breaking changes
to existing types and methods.

## ✨ Changes Added

**🔌 New endpoints**
- `client.organization().userStores().list(...)` — list organization user stores
- `client.organization().invitations().roles().list(...)` — `GET member-invitations/{id}/roles`
- `client.organizationDetails().delete(...)` — `DELETE /organizations/{id}`

**🧩 New types**
- **📦 User Stores** — `UserStore`, `ListUserStoresResponseContent`,
  `ListOrganizationUserStoresRequestParameters`
- **🔗 Cross-App Access** — `CrossAppAccessResourceApp`, `CrossAppAccessResourceAppConfig`,
  `CrossAppAccessResourceAppStatusConfig`, `CrossAppAccessResourceAppStatusConfigEnum`,
  `CrossAppAccessResourceAppStatusEnum`
- **🤝 Third-party client access** — `OrgThirdPartyClientAccessConfig`, `OrgThirdPartyClientAccessEnum`
- **🔐 SCIM provisioning** — `IdentityProvidersConfigProvisioningConfiguration` (+ `…OnLogin`,
  `…Scim`, `…ScimTokens`, `…ScimTokensScopesEnum`), and per-strategy config types
  `IdentityProviderConfigOidc` / `IdentityProviderConfigOkta` / `IdentityProviderConfigSamlp`
- **🎚️ Member access levels** — `OrganizationMemberAccessLevelEnum` (`none`, `readonly`,
  `limited`, `full`)
- **✉️ Invitation roles** — `GetMemberInvitationRolesResponseContent`,
  `DeleteMemberInvitationsRequestContent`
- **🔑 New OAuth scopes** for the added surfaces (`OauthScope`)

**🔧 Modified**
- `identityProviders().list()` gains filter params and raises `BadRequestError` on HTTP 400
- 📄 Pagination: `includeTotals` request param added, plus `total` and `totalIsCapped`
  on paginated responses
- `userStoreId` added to `MemberInvitation`
- SAML IdP gains `discoveryUrl`; `options` / `attributes` optionality adjusted

## ⚠️ Breaking Changes

- 🗑️ Removed `Automatic`, `Manual`, and `FedMetadataXml` from exported types — the ADFS
  metadata type is now `IdpAdfsOptionsRequestFedMetadataXml`
- 🔄 `domains().identityProviders().get()` renamed to `list()`
- 🔄 `invitations().delete()` resignatured to a batch shape
- 🔄 `members().get()` now returns `OrgMemberBase` **without** `roles` — fetch roles via
  `members().roles().list()`
- 🔄 SAML IdP: `cert` renamed to `signingCert`, and additional fields are now required
- ❗ ADFS IdP: `fedMetadataXml` is now required
- 🔄 `members().roles().unassign()` now calls `POST .../unassign-roles`

## 🛠️ Build Fix

The regenerated wire tests referenced types/method shapes absent from the generated
models, breaking `:compileTestJava`. Patched to compile against the actual generated
API; `./gradlew build` now passes. ✅

> ⚠️ These test edits are to generated files and will be overwritten on the next
> regeneration — the underlying generator inconsistencies should be fixed upstream.
